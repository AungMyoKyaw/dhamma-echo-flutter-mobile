# Desktop Palette Mobile Branding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Flutter mobile application's implemented visual palette match the current Dhamma Echo desktop palette while preserving the existing light-only Material 3 structure and launcher-icon pipeline.

**Architecture:** Keep the existing `DhammaEchoApp` and component-theme structure. Replace the stale green generated seed with an explicit Material 3 `ColorScheme` whose brand/surface roles are mapped from the desktop CSS tokens, so all widgets using `Theme.of(context).colorScheme` inherit the same desktop identity without screen-by-screen restyling. Keep platform icon generation in `tool/configure_platforms.py`; the AI-generated master/icon layers remain a separate asset input to that existing pipeline.

**Tech Stack:** Flutter 3.44.x / Dart 3.12+, Material 3, existing Python/Pillow platform configuration tooling.

## Global Constraints

- Desktop palette is the source of truth: `#8c3f08` primary, `#485b37` secondary, `#6e5014` tertiary, `#fcf9f2` background, `#ffffff` surface, `#f0eee7` soft surface, `#d5d1c8` border, `#2e2e2a` text, `#565550` muted text, `#8d3531` error.
- Light-only behavior remains unchanged.
- No new production dependency.
- Do not redesign screen layout, navigation, playback, downloads, typography, or spacing.
- Preserve existing Android adaptive icon and iOS icon generation pipeline.
- AI image generation is required for any replacement icon asset; if the image tool cannot access a usable image target, record the icon step as `BLOCKED` instead of substituting a non-AI-generated icon.

## Project-specific Ralph Loop

**Goal:** prove the mobile implementation uses the same brand palette as desktop without unrelated behavior changes.

**Current state:** the design spec already lists the desktop colors, but `lib/app/dhamma_echo_app.dart` still uses a green seed (`#2F5D50`) and a green-tinted background (`#F8FAF7`). The current launcher icon uses a dark green background (`#173F35`) and therefore does not match the current desktop palette.

**Acceptance criteria:**

- `ThemeData.colorScheme.primary == #8c3f08`.
- `ThemeData.colorScheme.secondary == #485b37`.
- `ThemeData.colorScheme.tertiary == #6e5014`.
- `ThemeData.scaffoldBackgroundColor == #fcf9f2`.
- Card/search/navigation surfaces use `#ffffff` and borders use `#d5d1c8` where the existing component themes expose those roles.
- Existing navigation selected-state foreground/background remain a matched Material role pair.
- No production dependency changes.
- Icon replacement is generated by the image-generation tool before integration; otherwise that slice is reported `BLOCKED`.

**Fast inner-loop validation commands:**

```bash
python3 tool/repository_check.py
python3 tool/test_configure_platforms.py
python3 tool/check_tests.py
flutter test test/ui/app_smoke_test.dart
flutter analyze --fatal-infos --fatal-warnings
```

**Full release-loop validation commands:**

```bash
make verify
make build-android
make build-ios
git diff --check
git bundle verify dhamma-echo-flutter-mobile-desktop-palette.bundle
```

**Known risks:** Flutter/Dart toolchains are not guaranteed to exist in the execution environment. The image-generation tool may not accept repository-contained images as an editable source target.

**Exit conditions:** all available repository checks pass; unavailable Flutter/platform or image-generation gates are reported `BLOCKED`; Git bundle is verified and clone-tested.
